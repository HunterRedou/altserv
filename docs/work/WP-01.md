# WP-01: Require TLS for the database in production

Status: open
Phase: 0
Depends on: none

## Goal
The app does not start with `PLATFORM=prod` if `DB_URL` does not set a TLS
mode that checks the server certificate.

## Read
- `internal/config/validation.go`
- `internal/config/config_test.go`
- `.env.example`

## Do
1. In `validate()`, read the `sslmode` query value from the parsed `DB_URL`.
2. When `PLATFORM=prod`, accept only `verify-full`.
3. When `PLATFORM=prod`, reject `disable`, `allow`, `prefer`, `require`,
   `verify-ca` and an empty value. Name `DB_URL` and `sslmode` in the error.
   Do not print the URL, because it can contain a password.
4. When `PLATFORM=dev`, accept every value.
5. Add a comment to `.env.example`: production needs `sslmode=verify-full`
   and the RDS CA bundle (`sslrootcert=`).

## Test
- `TestLoadRequiresVerifiedDatabaseTLSInProd`: a table test with each
  `sslmode` value for dev and prod.
- The error text does not contain the DB password.

## Done when
- Prod with `sslmode=disable` fails at startup.
- Prod with `sslmode=verify-full` starts.
- All existing config tests pass.

## Do not
- Change the dev default in `.env.example`.

## Notes
`require` encrypts but does not check the certificate. A man-in-the-middle
attack is then still possible. That is why prod accepts only `verify-full`.
