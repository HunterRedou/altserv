# WP-04: Separate the database roles

Status: open
Phase: 0
Depends on: none

## Goal
Migrations and the running app use different login roles. Neither is a
superuser or the RDS master user (doc 16).

## Read
- `internal/db/sql/schema/012_row_level_security.sql`
- `internal/db/tenant.go`
- `docs/runbooks/deployment.md`

## Do
1. Write `deployments/sql/roles.sql`. It is idempotent and creates:
   - `altserv_migrator`: LOGIN, owns the schema objects, runs goose.
   - `altserv_runtime`: LOGIN, member of `altserv_app`, `NOSUPERUSER`,
     `NOBYPASSRLS`, `NOCREATEDB`, `NOCREATEROLE`.
2. Take passwords from psql variables. Do not write a password in the file.
3. Write the order of steps into `docs/runbooks/deployment.md`: master user runs
   `deployments/sql/roles.sql`, `altserv_migrator` runs goose, the app connects as
   `altserv_runtime`.
4. Find out if the migrations need ownership changes for the new role. Write
   the result in Notes. Do not change existing migrations.

## Test
- `TestRuntimeRoleCannotEscalate` (DB test, skipped without `TEST_DB_URL`):
  as `altserv_runtime`, `CREATE TABLE` fails, `SET row_security = off` does
  not bypass RLS, and `DELETE FROM audit_events` fails.

## Done when
- The test passes on `altserv_test`.
- The app runs locally with a `DB_URL` for `altserv_runtime`.

## Do not
- Change migrations 001 to 027.
- Change the local dev setup that uses `postgres`. The new roles are optional
  in dev.
