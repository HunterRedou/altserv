# WP-15: Payment provider

Status: blocked
Phase: 3
Depends on: D-3, WP-05

## Goal
The payment provider chosen in D-3 activates and suspends tenants through
signed webhooks.

## Read
- `docs/work/decisions.md` (D-3)
- `cmd/tenantadmin/main.go` (from WP-05)
- `internal/billing/transmission.go` (the adapter and fake pattern)

## Do
1. Add `internal/payments` with a client interface and a fake client.
2. Add tables for subscriptions and webhook events. The event id is unique.
3. Add `POST /api/webhooks/<provider>`. It is public, has no CSRF, checks the
   signature, and is rate limited.
4. Map events: active to `valid`; payment failed to a grace period, then
   `suspended`. Never delete a tenant.
5. Add config for the provider. Prod rejects the sandbox mode.
6. Send only company data to the provider. Never send health data.

## Test
- A bad signature answers 401 and changes nothing.
- The same event twice changes the status once.
- A failed payment suspends, it does not delete.

## Done when
- The sandbox flow works on staging.
- `docs/compliance/processing-activities.md` lists the provider.

## Do not
- Remove VIES. WP-16 does that.
