# WP-14: Audit sink exporter

Status: blocked
Phase: 3
Depends on: WP-13, WP-09

## Goal
A background job exports new audit events to the sink from ADR-027.

## Read
- `docs/decisions/ADR-027-audit-sink.md`
- `internal/audit/repository.go`
- `retention_review.go` (as the pattern for a background job)

## Do
1. Add a table for the export position (last exported event id and hash).
2. Add a job that reads events after the position, writes them to the sink,
   then moves the position in one transaction.
3. Make the export idempotent: a retry writes the same object key.
4. Count errors in the job error metric.

## Test
- A fake sink receives each event once, also after a simulated crash.
- The hash chain detects a changed or missing event.

## Done when
- Staging events arrive in the sink.

## Do not
- Delete audit events from the database after export.
