# WP-05: Tenant status model and manual activation

Status: open
Phase: 0
Depends on: none

## Goal
An operator can activate or suspend a tenant without VIES. The pilot can then
start with any choice in D-3.

## Read
- `handler_verify_tenants.go`
- `internal/db/sql/queries/updateTenants.sql`
- `internal/db/sql/queries/sessions.sql`
- `cmd/catalogimport/main.go` (as the pattern for an operator tool)

## Do
1. Find the current CHECK constraint for `tenants.status`. Write the values in
   Notes.
2. Add a migration that allows `suspended`. Keep the existing values.
3. Make sure that login and session lookup accept only `valid`.
4. Add `cmd/tenantadmin` with `-tenant <id> -action activate|suspend`.
5. Write one audit event for each change: `tenant.activated` or
   `tenant.suspended`. Metadata: old status and new status only.
6. Refuse `activate` for a terminated tenant.

## Test
- A `suspended` tenant cannot log in, and an existing session stops working.
- `activate` on a `pending` tenant sets `valid` and writes one audit event.
- `activate` on a terminated tenant fails.

## Done when
- The tests pass.
- `docs/runbooks/deployment.md` describes the tool.

## Do not
- Remove VIES. WP-16 does that.
- Delete a tenant or its data.
